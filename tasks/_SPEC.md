# 正式任务集生成规范（内部执行用）

> 目标：生成 30 道题，**A / B / C = 10 / 10 / 10**。
> 每道题一个文件：`tasks/{task_id}.md`；B、C 类另出底稿答案：`tasks/keys/{task_id}.json` + `tasks/keys/{task_id}_calc.py`。
> 文件格式见 `tasks/_TEMPLATE.md`，**逐字按它写**。

---

## 一、分类判据（唯一依据，不得按题材判）

**分界不是「看起来串不串行」，而是「信息是不是前向流动」。**

| 类别 | 定义 | 自检问题 |
|---|---|---|
| **A 信息并行** | 每一段的内容**都能从材料直接推出** | 删掉中间某一段，后面各段**还能**写对吗？能 → A |
| **B 信息串行·短链** | 链长 3–5；第 i 步的输入是第 i−1 步**算出来的结果** | 删掉中间某一段，后面**算不出来** → 串行 |
| **C 信息串行·长链** | 链长 ≥ 段数，本题**取 N = 链长**，范围 8–12 | 同上 |

**重点：A 类里必须包含一部分「看起来串行、实际并行」的题目**——即**已知流程的逐步讲解**
（第一步、第二步……，但每一步的内容来自材料，而不是上一步算出的结果）。这类题是本实验真正的机会所在，必须出，不得漏。

**B/C 类的链必须真串行**：第 i 步至少要有一个输入来自第 i−1 步的**输出**。
如果所有步骤都只依赖材料里给定的常数，那它就是 A 类，不是串行题——**标签错了整个实验的解释就崩了**。

---

## 二、材料的硬性要求

1. **材料自足**：完成该题所需的**全部**参数、公式、规则、事实都写在材料里，
   读者不需要任何外部知识或检索。
2. **字数 800–1500 个中文字符**（用 Python `len()` 数，见 §五）。
3. **一道题一份材料**，题内逐字固定，不得在其中留占位符。
4. **不得写真实主体**：不出现真实公司名、真实人物、真实产品、真实事件。
   一律用代号（如「产品代号：星识 S1」「项目代号：青松」）。
5. B/C 类必须**数值唯一确定**：给定的公式与参数能算出唯一结果，且必须在材料里写清精度
   （如金额保留两位小数、功率保留两位小数、因子保留四位小数）。
6. A 类材料要把各段的要点**分列**清楚，使每段都能独立从材料推出。

---

## 三、分段方案与参数

- 段数：A 类固定 **N = 10**；B/C 类 **N = 链长**（B：3/4/5；C：8–12）。
- 每段对应材料里的哪一部分，必须在「分段方案」表里写死，一一对应。
- `max_tokens（A0/A1）`：N ≥ 8 时写 **3000**；N ≤ 5 时写 **1500**。
- `max_tokens（A2）`：一律写 **600**。

---

## 四、自检（必须真的做，不是复述）

对每道题做一次「删段」自检：

> 把中间某一部分（不要删第 1 或最后一段）删掉，**后面的部分还能不能写对 / 算对？**

- 能 → 信息并行（A）
- 不能 → 信息串行（B 或 C）

**必须选一个真的会造成影响的位置**去问，并把结论与理由写进文件的「自检记录」一节。
A 类题如果发现某段其实依赖上一段，说明分类错了，要改成 B/C 或重新设计材料。
B/C 类题如果发现某段其实不需要前一步结果，说明分类错了，要把该段改成真依赖。

**「自检记录」里一律不要出现任何由计算得出的具体数值**——那等于把答案提前写进题面。
只描述依赖关系（如「第 5 步的输入 X 只能由第 4 步算出」），不给数字。

---

## 五、B/C 类底稿答案

B/C 题必须产出可复核的底稿答案，**数字必须由 Python 脚本算出，不许手算**：

1. 写 `tasks/keys/{task_id}_calc.py`：用标准库，按材料里的公式和参数，逐段计算。
   运行它必须把结果以 JSON 打印到 stdout，字段：

   ```json
   {
     "task_id": "B-01",
     "chain_length": 3,
     "steps": [
       {"step": 1, "outputs": {"R1": 0.0, "E1": 0.0}, "uses_previous": []},
       {"step": 2, "outputs": {"R2": 0.0}, "uses_previous": ["R1"]}
     ],
     "final": {"C3": 0.0}
   }
   ```

   `outputs` 的键名必须与材料里用的符号名一致；`uses_previous` 列出该步用到了前哪一步的哪些输出。

2. 用 `/home/sparker/miniconda3/envs/llm/bin/python tasks/keys/{task_id}_calc.py > tasks/keys/{task_id}.json` 生成答案文件。

3. 自检：每条 `uses_previous` 必须非空（第 1 步除外）——**空就说明这段不依赖前面，不是串行题**。

- `tasks/{task_id}.md` 存在，且包含模板里的**全部**小节（类别 / 段数 / 链长 / 预期 k /
  max_tokens / 自检记录 / 原始材料 / 分段方案 / 大纲标题列表 / 任务要求）。
- 材料字数 800–1500。
- 「大纲标题列表」的条目数 = N，且与「分段方案」逐行对应。
- B/C 类：`tasks/keys/{task_id}.json` 与 `_calc.py` 都存在，且已运行验证过。
