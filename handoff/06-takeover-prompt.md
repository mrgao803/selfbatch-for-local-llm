# 06 · 交接提示词（复制粘贴给服务器上的 AI 助手）

> **用法：把本文件 §下方代码块里的内容原样发给服务器上的 AI 助手，同时上传整个 `handoff/` 目录。**

---

```
你现在接手一个研究项目。请先完整阅读随附的 6 份文档，然后按其中的规范工作。

【项目一句话】
验证「把一份长文档拆成 N 段并行生成，再用 k 轮『互相看见 + 一起修订』把它们对齐，
能否在 N/k 倍的时间里达到『一次写完』的质量」。

【你的角色】
你是出题人 + 裁判 + 执行方——三个角色都在你身上。
人类操作员只负责确认关键决策和抽样核对。

【第一步：先读完，不要提改进方案】
这套设计的每一个「奇怪」之处，01-brief.md 第五节都解释了为什么。
在你理解「为什么」之前提出的改进，大概率会破坏实验。

【阅读顺序】
1. README.md              总览、当前状态、待办清单
2. 01-brief.md            为什么——含所有约束的理由（最重要，先读它）
3. 02-protocol.md         实验协议 + 已冻结的评分表
4. 03-executor-rules.md   执行规范（带【硬性】标记的不可偏离）
5. 04-prompt-spec.md      全部提示词，可直接执行
6. 05-pilot-tasks.md      试点 3 题（含完整材料与分段方案）

【立刻要做的第一件事】
跑「阶段一：batch 耗时曲线」，见 03-executor-rules.md 第 3 节。
它不需要任务集，几小时就能出结果。测完只需要报告一个数：

    单步耗时比 = batch=10 的 decode 耗时 ÷ batch=1 的 decode 耗时

这个数决定后面是否值得继续。先报这个数，等操作员确认。

【四条绝对不能违反的规则】
1. 生成某一段时，绝对不得把其他段的正文放进提示词。
   （否则你替它做了串行工作，实验失去意义，作废重跑）
   允许放大纲（所有部分的标题），禁止放任何其他部分的正文。

2. 融合轮次里用新段落【替换】旧段落，不要把历史累积进提示词。
   历史轨迹留在文件系统里，不进提示词。

3. 模型输出得不好、跑题、格式错——照原样记录。
   不要重跑、不要修正、不要挑好的那次。只有请求报错才允许重跑并标注。

4. 评分表（02-protocol.md 第 6 节）已冻结。可以补充，不可以修改已定条目。

【任务集怎么办】
正式 20 道题需要你自己出，A/B/C = 8/6/6。
出题分类不要按题材选，要按「信息依赖结构」选——判据见 01-brief.md 第 2.2 节。
出完先交给操作员检查 A/B/C 分布有无偏向，确认后再跑。
必须先跑试点 3 题验证管线，管线通了再上正式题。

【为什么必须包含「预期会输」的题】
出题人即裁判，有自证动机。任务集里必须有 C 类（长链信息串行），预期它明显输。
如果分段在 C 类上也赢了，说明评分不可信，实验作废重做。
C 类是内置的照妖镜，不能省。

【完成标准】
- 阶段一的单步耗时比已报告并获确认
- 20 题 × 3 条件 × 3 seed 全部跑完
- 匿名化输出 + 三层质量判定（客观计数 / 分项打分 / 整体）
- k 随链长变化的曲线
- 按 02-protocol.md 第 10 节的判读规则给出结论

【一句话】
你的价值在于「不作主」。照做、如实记、别帮忙。

现在开始：先读完全部 6 份文档，然后运行阶段一，把单步耗时比报给我。
```

---

## 附：如果只需要跑阶段一（最小交接）

若暂时不想交接整个项目，只想让服务器 AI 先测那个关键数字，可以只发下面这段：

```
请帮我测一个推理性能的数字，需要严格按步骤做。

【要测的东西】
不同 batch size 下，单个 decode step 的耗时。

【步骤】
固定输入长度 2048 token，固定输出 256 token（必须设 ignore_eos=true，
不允许提前停止，否则长度不一致数据不可比）。

对 batch ∈ {1, 2, 4, 8, 16} 各做：
1. 先预热：同 batch 跑 3 次，丢弃
2. 再测量：跑 5 次，记录 prefill_ms 和 decode_ms
3. 取中位数（不要用平均值）

【要报的数】
单步耗时比 = batch=10 的 decode_ms ÷ batch=1 的 decode_ms

（若没测 batch=10，用 batch=8 或 16 插值并说明）

【附】
顺便报告：模型名与量化精度、显卡型号与显存、能否跑满 batch=10（显存不足就如实说）。
```
