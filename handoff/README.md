## 这是什么

一个实验项目，用来验证一个架构设想：

> **把一份长文档拆成 N 段并行生成，再用 k 轮「互相看见 + 一起修订」把它们对齐，能否在 `N/k` 倍的时间里达到「一次写完」的质量？**

若成立，N=10、k=2 时即 **5 倍加速**。

**背景：** 当前大模型必须逐 token 串行生成，推理受显存带宽限制，现有优化手段都只在缓解、没有取消这个瓶颈。本方案试图在结构层取消它。

## 第一件事：测一个数

**不要先跑任务。** 先跑 `03-executor-rules.md` 第 3 节的 batch 耗时测量。

它几小时能出结果，而且只需要一个数：

```
单步耗时比 = batch=10 的 decode 耗时 ÷ batch=1 的 decode 耗时
```

| 这个比值 | N=10, k=2 时的加速 |
|---|---|
| ≈ 1 | **5×** |
| ≈ 2 | 2.5× |
| ≈ 10 | **无收益，后面不用跑了** |

**它能提前几天告诉你这件事值不值得做。**

## 四条红线（违反即作废）

1. **生成某一段时，不得把其他段的正文放进提示词**——否则你替它做了串行
2. **融合轮次用新段替换旧段**，不要把历史累积进提示词
3. **输出照原样记录**，不重跑、不修正、不挑好的那次
4. **评分表已冻结**，可补充不可修改
