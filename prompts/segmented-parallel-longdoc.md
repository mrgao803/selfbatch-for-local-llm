# 分段并行长文生成 · 判定与执行协议

> 用法：交给具备「并发调用子任务」能力的 agent harness。
> 核心不是提示词模板，而是**第一步的判断**——判断错了，后面全错。

---

## 一、先问三个问题（不是一问）

### 第 1 问：删掉中间某一段，后面的段还能写对吗？

- **能** → 信息并行，**可切**，直接适用本协议
- **不能** → 信息串行，**不能按"段"切** —— 但**不等于不能并行**，继续问第 2、3 问

⚠️ **最容易误判、也最值钱的一类：「看起来串行、实际并行」。**
逐步教程、流程说明、参数清单、分项规则——表面是"第一步、第二步"，但每一步的内容都来自材料，
而不来自上一步算出的结果。**这类任务体量最大，也是这套方法真正值钱的地方。**

### 第 2 问：关键路径有多长？

任务不是一条直线，是一张 **DAG**。不可并行的不是"总工作量"，而是**关键路径（最长依赖链）**。

```
可用并行度 ≈ 总工作量 / 关键路径长度
```

- 关键路径 ≈ 总工作量 → 可用并行度 ≈ 1（纯链，如十步递推）
- 关键路径 ≪ 总工作量 → 大量并行空间（如"看起来串行"的流程讲解）

**第 1 问答"不能"，不等于第 2 问的答案是 1。** 它只说明不能按"段"切——
图里往往还有别的**非关键路径工作**可以铺开。

### 第 3 问：验证比生成便宜吗？

**这是最强的一问。** 只要验证器足够便宜，串行深度就不是硬约束——**它可以被"猜 + 验"吃掉**。

| 验证器 | 便宜？ | 后果 |
|---|---|---|
| 编译器 / 类型检查 / 测试 | ✅ 一秒扫完 | 代码场景的融合成本几乎消失 |
| 计算器 / 求解器 | ✅ | 数值链的深度可以被吃掉 |
| 形式化证明检查器 | ✅ | 证明可以"猜 + 验" |
| **让模型读两段判断是否一致** | ❌ **和生成一样贵** | **长文场景只能靠 k 轮互相看——成本就在这里** |

### 三问合起来

| 第1问 | 第2问 | 第3问 | 结论 |
|---|---|---|---|
| 能切 | — | — | ✅ 按段并行：`N / ((1+k) × 单步比)` |
| 不能切 | 关键路径 ≪ 总工作量 | — | ✅ 换切法：按 DAG 的独立分支切，不按"段"切 |
| 不能切 | 关键路径 ≈ 总工作量 | 验证便宜 | ✅ 分支 + 验证（买到的是**正确率**，时延未必） |
| 不能切 | 关键路径 ≈ 总工作量 | 验证也贵 | ❌ **放弃并行，老实串行** |

### 串行任务里的并行藏在五处

| # | 藏在哪里 | 例子 | 前提 |
|---|---|---|---|
| ① | 步内的偏序 | 同一步里两个互不依赖的子计算 | 一步内部不是全序 |
| ② | 分支搜索 | 同时试 B 种方向，按是否收敛筛 | 允许试错 |
| ③ | 投机执行 | 一次猜若干步，验证器一次全验 | **验证比生成便宜** |
| ④ | 换算法 | 线性递推「分块参数化 + 树形合并」：深度 D → D/K + log K | 链可组合（仿射可以，乘积断链） |
| ⑤ | 准备/预取 | 所有步的公式与依赖一次性铺开，只留数值推进是串行 | 材料里已给公式 |

反例（**禁止按段切**）：数学证明、逐步推导、连续计算、任何"下一步必须用上一步算出的数"的任务。
（注意：是禁止按**段**切，不是禁止并行——见第 2、3 问的出路。）

## 二、为什么有效（一句话）

单个请求输出时，每次只出 1 个 token，却必须把全部模型权重从显存搬运一遍。
**实测：此时显存带宽已用掉 90%，而算力利用率不到 1%。**

切成 N 段并行后，同一次权重搬运产出 N 个 token——**把闲置的算力填上了**。

实测（单卡 GB10 / 27B bf16 / 2048 上下文）：同时跑 64 条序列，总吞吐是单条的 **34 倍**，而每条序列自己的耗时只慢 88%。

## 三、执行步骤

1. **串行出大纲**（1 次调用）。此后固定不变，所有段共用。
2. **N 段并行生成**（N 次**并发**调用）。
   - 每段提示词里**只能有**：原始材料 + 大纲（只有标题）+ 本段的要求。
   - **绝对禁止**放入任何其他段的正文——否则你替它做了串行工作。
3. **k 轮融合**（每轮 N 次**并发**调用）。
   - 每轮把**全部 N 段**给每一段看，要求它与其余部分在术语、事实、数字、时间线上保持一致。
   - **用新段替换旧段**；历史留在文件系统里，**不要累积进提示词**。
   - 每轮测量改动量，衰减到阈值以下即停（不要凭"看起来一致了"提前停）。
4. 组装成一份文档。

---

## 四、参数怎么定

| 参数 | 规则 | 实测依据 |
|---|---|---|
| **N**（段数） | 在单步效率跌破 60% 前尽量大 | 效率：16→83%、32→68%、64→**53%**。**推荐 N = 16~32** |
| **k**（融合轮数） | 成本 ×(1+k)，下限 1（至少要一轮互相看见） | k=2 时总成本 3 倍 |

**成本公式：**

```
加速 = N / ((1 + k) × 单步比)
```

---

## 五、三条红线

1. **生成任何一段时，不得让它读到他段正文**（只能给材料 + 大纲）
2. **融合轮用新段替换旧段**，不把历史累积进提示词
3. **输出照原样记录**，不重跑、不修正、不挑好的那次

---

## 六、什么时候不要用

| 情况 | 原因 |
|---|---|
| 任务信息串行（证明、推导、连续计算） | 深度是问题本身，切开必错 |
| N 个交付物之间**不需要一致** | 不必付融合的 k 轮成本 |
| 按 token 计费、且服务商批已填满 | 你付 `(1+k)` 倍的钱换时延，不划算 |
| 自有硬件、单用户长文档 | ✅ **甜点区**：省时延也省机时 |
